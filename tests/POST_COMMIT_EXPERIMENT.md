# Эксперимент: ошибка до операции и потеря ответа после операции

Статус: спроектирован, не выполнен. Результаты не подставлены заранее.

## Цель

Показать, какие ошибки повторных побочных эффектов обнаруживает модель потери ответа после завершения upstream, в сравнении с ошибкой, внедрённой до вызова upstream. Основание сравнения — описанная в §3.1 S01 модель, а не утверждение об ограничениях всех chaos-инструментов.

## Стенд и варианты

orders вызывает payments POST /charge; при сетевой ошибке делает одну повторную попытку. Вариант BUG не обеспечивает идемпотентность. Вариант FIX сохраняет и повторно использует idempotency key, а payments гарантирует одно списание на ключ. Перед запуском seed восстанавливает пустой журнал платежей. Для данного теста inventory всегда доступен.

| Режим | Момент вмешательства | Ожидаемая проверка, не измеренный результат |
|---|---|---|
| CONTROL | Нет отказа | Одно успешное списание |
| PRE | Ошибка до передачи первого запроса payments | Первая попытка не меняет ledger; проверить эффект retry |
| POST | payments завершает запись, затем ответ первой попытки теряется | Проверить, создаёт ли retry второе списание |

Один и тот же checkout, сумма, retry policy, reset и oracle во всех режимах. Сравнить BUG и FIX во всех трёх режимах, по 30 запусков каждой ячейки. Никакие числа из UX-макета не переносить в результаты.

Oracle: число подтверждённых списаний по checkout_id, уникальность operation key и итог операции. ORIGINAL_FAILURE — число списаний >1 для исходного инварианта. Ноль списаний при неуспешном checkout — отдельный исход, а не «двойная оплата». Для FIX одного HTTP 200 недостаточно: ledger также должен пройти проверку.

Сохранить порядок upstream commit → proxy drop → retry; без подтверждения commit пометить запуск как некорректный для POST. Не моделировать POST простым HTTP 503 до upstream — это другой эксперимент.

## Выводы, которые допустимы после измерений

Если POST обнаруживает дефект BUG, который PRE не обнаруживает, можно утверждать преимущество данной модели отказа на данном классе сценариев. Нельзя делать вывод о превосходстве всей платформы над Reynard или мировыми аналогами. Если обе модели находят дефект, отразить отсутствие предполагаемого отличия.
