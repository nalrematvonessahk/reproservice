# Требования и приёмка

Версия 0.1, проектные требования, ожидают проверки интервью и руководителем. Must — обязательный MVP; Should — после Must; Could — расширение. Численные пороги — цели, не результаты. Для каждой строки тест TC-<ID> определён её критерием; протокол сохраняет условия и доказательство.

| ID | Приоритет | Требование | Критерий приёмки | Ответственный |
|---|---|---|---|---|
| FR01 | Must | Импортировать сценарий | Валидный JSON принят; неизвестное действие и отсутствующий selector отклонены до запуска. | Tamerlan |
| FR02 | Must | Сбросить стенд | Перед каждым кандидатом восстановлены seed и изолированная БД; при ошибке reset запуск не начинается. | Aldiyar |
| FR03 | Must | Сопоставить HTTP-событие | operation/service/method/path/attempt дают одно совпадение; ноль или несколько → INAPPLICABLE. | Tamerlan |
| FR04 | Must | Внедрить задержку и HTTP-ошибку | Задержка и код соответствуют сценарию; ошибка синтезируется до отправки upstream; действие отражено в журнале. | Tamerlan |
| FR05 | Must | Потерять успешный ответ | Upstream завершает операцию, затем downstream-соединение закрывается без передачи ответа; журнал хранит оба события. | Tamerlan |
| FR06 | Must | Проверить инвариант | API/SQL-проверка возвращает ID нарушения, ожидаемое и фактическое значение; инфраструктурный сбой не считается нарушением. | Aldiyar |
| FR07 | Must | Повторить сохранённый сценарий | Сохранены digest, seed, timeouts и selector; несовпадение окружения блокирует запуск до явного создания новой версии. | Tamerlan |
| FR08 | Must | Сократить вмешательства | ddmin, последовательное удаление и вариант с приоритизацией получают одинаковые сценарий, валидацию и бюджет; результат сохраняет исходный invariant ID. | Aldiyar |
| FR09 | Must | Остановить запуск | Cancel прекращает новые кандидаты, освобождает ресурсы и сохраняет CANCELLED, не PASS. | Aldiyar |
| FR10 | Must | Показать историю и таймлайн | Фильтры по сервису и типу события, выбранное событие раскрывает selector и результат вмешательства. | Askhat |
| FR11 | Must | Сравнить версии | Для исходной и исправленной версии показаны digest, одинаковый seed/сценарий и отдельные результаты; нет вывода «исправлено» без повторов. | Askhat |
| FR12 | Must | Экспортировать результат | JSON содержит schema_version, конфигурацию, outcome и ссылки на события; секретные заголовки отсутствуют. | Askhat |
| FR13 | Should | Управлять порядком запросов | Зависимости образуют DAG; цикл отклоняется; release разрешён только после выполнения предшественника. | Tamerlan |
| FR14 | Could | Запускать из CI | CLI возвращает различные exit codes для PASS, нарушения и инфраструктурной ошибки. | Aldiyar |
| NFR01 | Must | Изоляция | API слушает localhost; тестовая сеть отделена; произвольный compose/SQL из интерфейса не исполняется. | Tamerlan |
| NFR02 | Must | Конфиденциальность | Authorization/Cookie/Set-Cookie заменены маской; контрольный секрет отсутствует в JSON и логах. | Tamerlan |
| NFR03 | Must | Воспроизводимость | Цель: ≥27 из 30 повторов поддерживаемого сценария дают исходный invariant ID; доля и доверительный интервал публикуются. | Aldiyar |
| NFR04 | Should | Накладные расходы | Цель: p95 дополнительной задержки прокси без fault ≤20 ms при 100 req/s на описанном стенде; отчёт сохраняет спецификацию машины. | Tamerlan |
| NFR05 | Must | Удобство | Цель: 4 из 5 представителей пользователей без подсказки открывают сценарий, находят нарушение и экспортируют результат за 5 минут. | Askhat |
| NFR06 | Must | Ограничение ресурсов | Бюджет 100 запусков, включая подтверждения, либо 10 минут на сокращение; завершение по первой границе с явным BUDGET_EXHAUSTED. | Aldiyar |
