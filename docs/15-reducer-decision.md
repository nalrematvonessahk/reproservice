# ADR-005: какие зависимости разрешено использовать при сокращении

Статус: предложено после проверки литературы; ожидает review команды и руководителя.

## Обнаруженная проблема

В первоначальном плане слово «зависимость» было слишком широким. Если в исходном запуске событие B произошло после A, это не доказывает, что B невозможно без A. Удаление вмешательства может открыть другой путь исполнения. Безоговорочное отбрасывание такого кандидата способно скрыть более короткий воспроизводимый сбой.

## Решение

Разделить два вида связей:

1. **Явная предпосылка сценария:** действие B определено как разрешённое только после выполнения действия A. Она задаётся контрактом сценария, проверяется валидатором и применяется одинаково во всех сравниваемых алгоритмах.
2. **Наблюдавшаяся связь:** получена из исходной трассы. Используется для приоритизации кандидатов, но не является достаточным основанием считать их невозможными.

Базовый вариант — ddmin с общей проверкой корректности сценария. Экспериментальный вариант — та же проверка плюс выбор порядка удаления блоков на основе наблюдавшихся связей. При одинаковом score использовать стабильный порядок ID. Такой дизайн не создаёт искусственного преимущества за счёт отсутствия обязательной валидации у baseline.

Черновая эвристика: сначала пробовать удалять блоки, которые слабо связаны с событиями проверяемого бизнес-инварианта; связь задаётся прозрачной функцией по трассе. Не называть близость в графе доказанной причинностью. Формулу score зафиксировать до основного эксперимента; результаты её настройки на отладочных сценариях не включать в итоговую оценку.

## Дополнительный baseline

Простое последовательное удаление по одному вмешательству с повторным проходом после принятого удаления. Оно показывает, оправдывает ли усложнение алгоритма затраты относительно понятного инженерного решения. Все методы используют один runner, oracle, кэш и одинаковый бюджет подтверждений.

## Проверки корректности

- B встречается после A, но существует без A: кандидат не отбрасывается по одной трассе.
- B требует A по явному контракту: кандидат отклонён одинаково всеми алгоритмами.
- Кандидат вызывает другой invariant ID: не принимается.
- Все графовые scores одинаковы: результат порядка стабилен.
- Бюджет кончился во время подтверждений: кандидат не считается подтверждённым.

## Последствия

Требуется обновить формулировку H1: влияние порядка кандидатов на стоимость сокращения, а не «пропуск заведомо невозможного без общей валидации». Возможен нулевой или отрицательный эффект. Это допустимый результат исследования.
