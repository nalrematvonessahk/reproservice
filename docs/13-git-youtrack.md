# Git и YouTrack

Удалённый репозиторий и сервер YouTrack пока не подключены. PLAN-xx в backlog.json — локальные номера, не реальные issue IDs.

1. Создать приватный GitHub/GitLab repo, пригласить участников с их личными аккаунтами. Заполнить URL в README.
2. Каждый участник настраивает собственные git user.name/user.email. Не создавать коммиты от имени других участников.
3. Проверить и внести пакет первым честно датированным коммитом с указанием помощи ассистента. Дальше фиксировать реальные изменения небольшими коммитами.
4. Создать YouTrack project, добавить участников. Поля: State, Priority, Assignee, Due Date, Type. Состояния: Open → In Progress → Review → Done; Blocked отдельно. Не переводить черновики в Done без проверки.
5. Импортировать подготовленные задачи или создать вручную. scripts/import_youtrack.py сначала выполнить без --apply: он покажет тела запросов, ничего не отправляя. При реальном импорте нужны URL, ID проекта, токен в переменных окружения. Имена/даты/приоритеты будут в описании: назначить реальные custom fields вручную и сверить владельцев.
6. Ветка: feat/<real-issue-id>-short-name; PR содержит ссылку на задачу, критерий и проверку. Другой участник проводит review. main защищена от прямого push; минимум одно одобрение.
7. Перед сдачей проверить ссылки, согласование и материалы. Создать аннотированный тег pre-defense-1 только на проверенном commit. Следующие теги: pre-defense-2 и final-pre-defense. Сданные теги не переносить; исправления — новый commit и согласованный дополнительный тег.

## Первый запуск на Windows

Открыть PowerShell в распакованной папке. `git init -b main` (если repo ещё не создан), затем `git status`. Настроить свою идентичность, проверить файлы, затем `git add .` и `git commit -m "Prepare initial thesis proposal and review materials"`. URL remote берётся из созданного вами репозитория; не вставлять выдуманный URL. `git remote add origin <REAL_URL>` и `git push -u origin main` выполняются после создания remote.

Импорт API основан на [документации JetBrains](https://www.jetbrains.com/help/youtrack/devportal/api-howto-create-issue.html). Скрипт хранит журнал созданных IDs, но при сетевой ошибке после отправки нужно проверить сервер вручную перед повтором, чтобы не создать дубль. Токен в Git не сохранять.
