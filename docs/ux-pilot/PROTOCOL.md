# DEMO-45: протокол UX-пилота (NFR05)

Требование NFR05 (`docs/06-requirements.md`): 4 из 5 представителей пользователей без подсказки открывают сценарий, находят нарушение и экспортируют результат за 5 минут.

**Статус: пилот не проведён.** В репозитории нет ни одной записи участника; файл `results-template.csv` содержит только заголовок. Результаты вносятся только из реальных сессий. Протокол должен прочитать и принять владелец задачи вместе с командой.

## Участники

- 5 человек из целевой аудитории: backend-разработчики, инженеры автоматизации тестирования, инженеры платформы (`docs/02-user-research.md`). Участники, которые уже видели интерфейс или помогали его делать, в зачёт не идут.
- Получить устное или письменное согласие на заметки. В репозитории хранить только код участника (`UX-01` … `UX-05`), без имён, контактов и записей экрана. Контакты хранятся отдельно и приватно.

## Подготовка стенда

1. Поднять стенд: `docker compose -f deploy/docker-compose.yml up -d --build`; убедиться, что контроллер отвечает на `http://127.0.0.1:7000`.
2. В `src/web`: `npm install` и `npm run dev`; открыть `http://localhost:5173` в чистом окне, пустое состояние.
3. Для проверки мобильной раскладки отдельный сеанс в окне 390 px (участникам не нужен, проверяет модератор по чек-листу ниже).
4. Один модератор и один наблюдатель с секундомером. Экран участника записывается только с его согласия и не коммитится.

## Задание участнику (читается вслух, без объяснения кнопок)

> У интернет-магазина клиентов иногда списывают деньги за заказ дважды. Откройте инструмент, воспроизведите эту ошибку, найдите, какое вмешательство её вызывает, сократите сценарий до необходимого и сохраните результат в файл.

Модератор не подсказывает названия кнопок и разделов. Участнику разрешено думать вслух. Ограничение — 5 минут с момента, когда он видит экран.

## Контрольные точки (отмечать время от начала)

| № | Что должно произойти | Что считается успехом |
|---|---|---|
| 1 | Открыть сценарий | Выбран пример и нажато «Validate & load scenario»; появилась версия (`version_id`) |
| 2 | Запустить | Нажато «Start run»; получен статус `ORIGINAL_FAILURE` |
| 3 | Найти нарушение | Открыто событие `fault/dropped` и участник своими словами объясняет, что ответ платежей потерян после успеха |
| 4 | Сократить | Нажато «Reduce»; участник называет оставшееся вмешательство |
| 5 | Экспортировать | Нажато «Export JSON», затем «Download file» (или участник сохранил JSON иным способом) |

Задача выполнена, если пройдены точки 1–5 в пределах 5 минут без подсказки модератора. Подсказка (любое слово модератора по существу интерфейса) переводит попытку в «неуспех».

## Что записывать

Для каждого участника заполняется одна строка `results-template.csv`:

- время до каждой контрольной точки в секундах (пусто, если точка не достигнута);
- итог: `success`, `success_with_hint` или `fail`;
- число подсказок и ошибочных нажатий;
- непонятные формулировки и места, где участник остановился (дословно, коротко);
- замечания по клавиатуре, контрасту и переносу текста, если они возникли.

Критерий NFR05 выполнен, если `success` у 4 из 5 участников. Результат записывается как есть, включая провал; выводы делаются только после всех пяти сессий.

## Чек-лист модератора для 390 px и клавиатуры (отдельно от участников)

- Окно 390 px: нет горизонтальной прокрутки на всех шагах, кнопки нажимаются без увеличения.
- Только клавиатура: Tab проходит все элементы, включая «Upload file»; фокус виден; Enter и пробел работают на кнопках и флажках.
- Курсор в поле JSON не «ловит» Tab (при необходимости зафиксировать как замечание).
- Режимы: тёмная тема ОС и увеличенный масштаб текста до 200 %.

## После пилота

1. Внести строки в `results-template.csv` (переименовать в `results.csv`, коммит от автора, который проводил сессии).
2. Обновить `docs/08-ux.md` и `docs/11-readiness.md`.
3. Закрыть DEMO-45 только после этого; если цель 4 из 5 не достигнута, завести задачи на найденные проблемы.
