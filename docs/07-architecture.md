# Архитектура и контракты

Редактируемые схемы: diagrams/*.drawio; читаемые версии: *.svg. Это проект архитектуры, а не описание уже работающего backend.

## Границы системы

Инженер управляет платформой через браузер. Контроллер запускает только заранее разрешённый тестовый стенд Docker Compose. HTTP-прокси находится между сервисами orders, payments и inventory. Метаданные платформы отделены от PostgreSQL тестового приложения. Платформа не направляет сбои в production.

## Компоненты

- Web UI: конфигурация сценария, состояние запуска, таймлайн, сравнение и экспорт.
- Controller API: валидация, сериализация запусков, жизненный цикл, отмена; localhost.
- Proxy/scheduler: сопоставление событий, внедрение вмешательств, журнал причинных связей.
- Runner/reset: проверка image digest, восстановление seed, health checks, запуск нагрузки, cleanup.
- Oracle: разрешённые API/SQL-проверки; возвращает конкретный invariant ID.
- Reducer: обычный ddmin и dependency-aware вариант; обращается к одному runner/oracle.
- Metadata store: scenario/version/run/event/candidate/assertion; append-only события и итоговый статус.

## Последовательность

VALIDATING → RESETTING → READY → RUNNING → ASSERTING → COMPLETED. Из каждого рабочего состояния возможны CANCELLED и INFRA_ERROR. COMPLETED отдельно содержит PASS, ORIGINAL_FAILURE, OTHER_FAILURE, TIMEOUT или INAPPLICABLE. TIMEOUT не равен исходному нарушению, кроме заранее определённого инварианта времени с тем же ID.

Перед кандидатом удаляется только принадлежащий этому run тестовый volume; посторонние контейнеры не затрагиваются. После reset сверяются хеш seed и health checks. До запуска нельзя выбрать произвольную shell-команду или SQL: используются ID заранее проверенных фикстур и проверок.

## Событие и стабильное сопоставление

Event: event_id, run_id, logical_operation, source, target, method, normalized_path, attempt, parent_event_id, monotonic_offset_ms, action_id, phase, result. traceparent/tracestate [T06] связывают трассу, но случайный trace ID не является ключом повторного сопоставления.

Selector: logical_operation + source + target + method + normalized_path + attempt. Для MVP номер попытки детерминированный и задаётся тестовым драйвером; конкурентные неоднозначные совпадения запрещены. Если событие не наступило в окне ожидания, исход INAPPLICABLE. Прокси удаляет чувствительные заголовки из журнала; тела запросов по умолчанию не сохраняются.

## Сокращение

1. Подтвердить исходное нарушение на полном наборе вмешательств.
2. Разделить множество вмешательств на подмножества, проверять удаления стандартным ddmin.
3. Общие явные предпосылки сценария проверять одинаково для всех алгоритмов. В варианте dependency-aware использовать наблюдавшиеся связи для порядка кандидатов; не отбрасывать кандидата только по связи в исходной трассе. См. ADR-005.
4. Для каждого допустимого кандидата выполнить reset, сценарий и oracle. Принимать только ORIGINAL_FAILURE с тем же ID; подтверждать принятый кандидат тремя повторами (3/3).
5. Остановиться при невозможности удаления, лимите бюджета или отмене. Сохранить лучший подтверждённый кандидат и причину остановки.

Повторные подтверждения расходуют общий бюджет. При флуктуациях кандидат отклоняется и помечается unstable. Исходный полный сценарий тоже проверяется одинаково для обоих алгоритмов. Удаляются вмешательства, а не бизнес-запросы. Нельзя заявлять глобальный минимум; 1-minimal допускается только если все одиночные удаления проверены и дают отрицательный результат в принятых условиях.

## Черновой API

POST /api/scenarios → validation + version ID; POST /api/runs → 202/run ID; GET /api/runs/{id}; GET /api/runs/{id}/events?cursor=; POST /api/runs/{id}/cancel; POST /api/runs/{id}/reduce; GET /api/runs/{id}/export. Операции запуска имеют idempotency key, повторный POST не создаёт второй run. Параллельный запуск при занятом стенде получает 409. JSON schema_version=1. Ошибка содержит code, message, field и correlation_id.

## Что не обещаем

Нет полного детерминизма ОС, потоков или часов. Не поддерживаются очереди, Kubernetes, произвольный TLS-трафик и production. Корректность на демонстрационном стенде не означает переносимость на любую систему.
